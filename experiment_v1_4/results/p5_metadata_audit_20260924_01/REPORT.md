# P5 CPU probe 결과 분석 — 2026-09-24

CPU probe는 3,510/3,510개 반환되었으며 전부 계산 성공(passed)이다. 이는 가설 통과 또는 P5 전체 완료 판정과 다르다. 원본 production cache가 없는 metadata 반환 감사이며, P5 최종 독립 검증은 남아 있다.

## 검증 범위와 재현성

- 사용자 Desktop의 index/ZIP을 데이터로만 취급했다. 외부 SHA256 `02d528327eb5de6defca6d6456eca7593b75e49fdf28dca5a7cb4faab6fcd16e`, 71,722,987 bytes 및 내부 3,821개 파일 checksum 검사를 통과했다. 상세 결과는 `analysis.json`을 따른다.
- 동결 r2 계약, 예약 READ train/val/test 50,000/10,000/20,000개 라벨·순서를 로컬 corpus와 대조해 일치를 확인했다. Cache marker 240개는 3 seed × trained/init × 3 split의 quota/offset/checkpoint/label hash를 기록한다.
- 3,510개 작업 모두 반환, seed당 1,170개. 누락·NA·기록된 optimizer 실패 없음. 이전 snapshot의 550개 결과는 바이트 단위로 동일하다.
- Support 표 10,530개, 저장된 validation trace의 선택 순서, 계수 shape/유한성, confusion matrix 기반 BA/macro-F1를 검산해 일치를 확인했다. 원시 activation에 대한 독립 계수·선택 재검산은 아직 아니다.
- 기록된 BA/F1 bootstrap 5,250개 평가 각각 1,000 valid draws. Binary AUROC 4,500개 각각 1,000 valid draws. 나머지 750개는 다중 클래스여서 binary AUROC가 적용되지 않는다. CI/AUROC 자체는 저장된 보고값이며 원시 예측으로 재계산하지 않았다.
- 계산 시간 합계 95,928.38초 = 26.65시간. 파일에 저장된 작업 시간의 합으로, I/O·중단·재개를 포함한 전체 경과 시간이 아니다.

16-class 전체 상태 full h BA는 block 0에서 9.59–12.18%, block 11에서 14.96–16.21%다(우연 BA 6.25%). 읽는 변수의 현재 값이 거의 완벽히 읽혀도 전체 4-bit 상태가 같은 선형 probe로 완벽하게 복원되는 것은 아니다. 이는 선형 접근성의 한계이며 전체 상태 정보가 없다는 증거는 아니다. Query 변수는 token/position 기준선에서도 100%이므로 높은 query probe 점수를 상태 계산의 증거로 보지 않는다.

## 완료 판정과 다음 단계

CPU probe 계산과 metadata 결과 반환은 완료됐다. 하지만 production NPZ 배열이 이번 ZIP에 없으므로 배열 checksum/row_indices/shape/dtype/유한성, train-only 전처리 통계, activation에 대한 저장 계수의 예측 재현, validation 선택 및 cluster bootstrap/AUROC의 독립 감사가 남아 있다. GPU smoke 및 cache 완료 marker는 해당 실행의 기록이지 원본 배열에 대한 독립 검증의 대체물이 아니다.

원본 cache가 있는 Drive/Colab 환경에서 이를 독립 감사하거나 cache를 회수해 감사한 뒤 P5 완료·registry·Git 업데이트와 P6 진입을 진행한다. 현재 단계에서는 모델 추론·probe fitting·test 기반 재선택·GPU 재추출을 수행하지 않았다.
